

## Лабораторная работа № 4. Основы работы с системой контроля версий Git и веб-сервисом GitHub.

## Цель работы
Изучить базовые концепции контроля версий, приобрести практические навыки установки и настройки Git, создания локальных и удалённых репозиториев, а также организации структуры для хранения последующих лабораторных работ по программированию.

## Краткие теоретические сведения
Git — это распределённая система контроля версий. Она позволяет фиксировать изменения в файлах (делать «снимки» проекта — коммиты), возвращаться к предыдущим версиям кода и безопасно вести разработку.
Локальный репозиторий — скрытая папка .git на компьютере, где хранится вся история изменений проекта.
Удалённый репозиторий — копия проекта, размещённая на сервере в сети (в данном случае на GitHub). Служит для резервного копирования и демонстрации кода.
Коммит (Commit) — сохранённое состояние проекта с уникальным идентификатором. Каждое сохранение сопровождается осмысленным описанием выполненной работы.

## Ход работы
Для начала я скачала установочный файл Git с официального сайта git-scm.com и запустила установщик, оставив все параметры по умолчанию. После завершения установки проверила её корректность в терминале командой git --version, и на экране отобразилась текущая версия программы, что подтвердило успешную установку. Затем я выполнила глобальную настройку Git, указав своё имя и адрес электронной почты командами git config --global user.name и git config --global user.email; для email использовала тот же адрес, на который зарегистрирован аккаунт на GitHub. Далее создала корневую папку prolabs, перешла в неё через терминал и инициализировала Git-репозиторий командой git init, после чего внутри папки появилась скрытая директория .git. Внутри корневой папки я создала каталог первой лабораторной работы llb1 и рабочий файл main.py. Проверив состояние репозитория командой git status, я увидела, что папка llb1 подсвечена красным как неотслеживаемая, после чего подготовила файлы к сохранению командой git add . и сделала первый коммит с описанием «Initial commit: create structure and llb1». Затем зашла на сайт github.com, вошла в свой аккаунт и через иконку «+» создала новый репозиторий с именем prolabs, выбрав тип Public и оставив пустыми все галочки инициализации, так как локальный код уже существовал. После создания репозитория GitHub показал страницу с подсказками, откуда я скопировала и поочерёдно выполнила три команды: git remote add origin, git branch -M main и git push -u origin main. При первом выполнении git push система открыла окно браузера для авторизации на GitHub, и я подтвердила доступ. Обновив страницу репозитория в браузере, я убедилась, что структура папки llb1 появилась в удалённом репозитории. Отчёт к лабораторной работе я оформила в формате Markdown.

## Итоги работы
В ходе выполнения лабораторной работы я установила и настроила систему контроля версий Git, создала локальный репозиторий с правильной структурой каталогов для хранения лабораторных работ, выполнила первый коммит с осмысленным описанием, создала публичный удалённый репозиторий на GitHub, связала локальный репозиторий с удалённым и отправила код командой git push, а также освоила оформление отчётов в формате Markdown. Созданная структура папки prolabs позволит в дальнейшем вести все последующие лабораторные работы в едином репозитории: для каждой новой работы достаточно создать новый каталог, сделать коммит и отправить изменения командой git push, при этом ссылка на репозиторий не меняется, и преподаватель всегда сможет увидеть актуальное состояние работ.
